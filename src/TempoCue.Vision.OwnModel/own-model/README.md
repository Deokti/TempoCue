# Веса модели TempoCue

Три файла, которые отдаёт репозиторий `tempocue-vision-model`. Лежат в
репозитории намеренно: без них выбор «Модель TempoCue» в настройках просто не
появится, а собирать приложение из двух источников ради трёх мегабайт незачем.

| Файл | Что это |
|---|---|
| `detector.onnx` | «где значки»: кадр 320×320 → карта центров 80×80 |
| `identity.onnx` | «кто это»: вырез 32×32 → доли по классам |
| `model.json` | словарь классов и все числа разбора |

## Откуда взялись

Обучены на синтетических кадрах; корпус настоящих кадров в обучении не
участвует и служит только проверкой. Нынешние веса — `detector-05` и
`identity-08` модельного репозитория.

Пересобираются одной командой оттуда:

```
.venv/Scripts/python tools/export_onnx.py \
    --detector out/detector-05/best.pt --identity out/identity-08/best.pt \
    --out out/onnx
```

Экспорт сверяется с PyTorch на настоящих кадрах и отказывается записывать файлы
при расхождении больше `1e-4`.

## Чего здесь нельзя делать

**Не подменяйте один файл из другой пары.** Детектор и опознание обучались
вместе, но связывает их не это, а `model.json`: там словарь классов, порог
вершины, шаг карты и сторона выреза. Файл от другого обучения даст молча
неверные ответы, а не ошибку.

**Не переносите числа из `model.json` в код.** Они свойство этих весов, а не
приложения. Продублируешь — при следующем обучении файлы разойдутся с кодом
беззвучно.

## Чего эта модель пока не умеет

Список незакрытого с размером приза по каждому пункту — в `docs/deferred.md`
модельного репозитория. Коротко: два значка ближе восьми пикселей друг к другу
разделяются не всегда, и узнавание значка со свечением возврата держится
нетвёрдо.
