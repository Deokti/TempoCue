# Корпус replay-кадров с ручной разметкой

Здесь хранятся сохранённые кадры `.tempocue-vision` и их ручная разметка.
`MinimapReplayCorpusTests` прогоняет распознавание по каждому кадру и сравнивает
результат с разметкой; ухудшение относительно записанных допусков ломает тест.

## Как собрать кадр

1. Во время матча открой `Настройки` → `Мониторинг карты`.
2. В момент ошибки — рамка на миньонах, башне или другом объекте — нажми
   `Сохранить кадр для replay`.
3. Назови файл по сути дефекта, например `minions-as-ally-01.tempocue-vision`,
   и положи его в эту папку. Формат не содержит Riot ID и имён призывателей.

## Как разметить кадр

Рядом с кадром создаётся файл с тем же именем и суффиксом `.labels.json`, например
`minions-as-ally-01.tempocue-vision.labels.json`:

```json
{
  "schemaVersion": 1,
  "regions": [
    { "x": 100, "y": 120, "width": 25, "height": 25, "kind": "Champion",
      "championId": "Anivia", "affiliation": "Enemy" },
    { "x": 40, "y": 200, "width": 20, "height": 18, "kind": "MinionWave",
      "affiliation": "Ally" },
    { "x": 60, "y": 80, "width": 16, "height": 16, "kind": "Tower" }
  ],
  "allowedFalsePositives": 1,
  "allowedMissedChampions": 0
}
```

Правила:

- координаты задаются в канонической системе кадра `320 × 320`;
- `Champion` размечает каждый действительно видимый значок чемпиона и обязан
  называть `championId`; сторона указывается, когда она известна;
- `Tower`, `MinionWave`, `Ward`, `DeadChampion`, `Other` фиксируют hard
  negatives — объекты, которые распознаватель не должен подтверждать;
- допуски записывают известное текущее поведение: при добавлении кадра с ещё не
  исправленным дефектом допуск равен фактическому числу ошибок, а после
  улучшения распознавателя допуски ужесточаются в том же изменении;
- разметка — утверждение об истине; baseline внутри `.tempocue-vision` остаётся
  снимком прежнего поведения и истиной не является.

Кадр `overlapped-sett-missed-08` фиксирует отдельный regression-сценарий:
частично перекрытые Teemo и Sett создают две области, но локально портрет Sett
сильнее напоминает уже распознанную Diana. Корпус требует сохранить все шесть
видимых чемпионов без ложных подтверждений, проверяя назначение в контексте состава.

Кадр `teemo-and-ambessa-unknown-to-model-11` — единственный, где штатный распознаватель
собирает весь состав без ошибок: семь чемпионов, ноль пропусков, ноль ложных. Он снят
при включённом экспериментальном режиме, поэтому его baseline — ответ нейросетевой
модели, а не наш; сравнение с разметкой показывает, что модель теряет там Teemo
(перерисованный значок) и Ambessa (вышла после патча, на котором её обучали).

Кадр `overlapped-tristana-behind-blitzcrank-12` фиксирует предел распознавания по
одному кадру. Tristana закрыта портретом Blitzcrank так, что виден только ободок
союзного кольца; личность установлена исключением — остальные четверо союзников
найдены в других местах кадра. Опознать её по пикселям нельзя, поэтому допуск на
пропуск здесь постоянный. Второй допуск описывает следствие этого пропуска: свободный
слот Tristana в составе достаётся иконке союзной базы в левом нижнем углу. Ужесточать
допуск ложных, не научившись сначала видеть перекрытие, нельзя — исчезнет причина, а
не симптом.

## Записи последовательностей

Файл `.tempocue-sequence` хранит несколько подряд идущих кадров одного матча и
существует для другого вопроса, чем корпус одиночных кадров.

Корпус отвечает, **скольких** участников распознаватель находит. Запись отвечает,
находит ли он их **на каждом кадре**. Игроку видна вторая величина: отметка либо
держится на чемпионе, либо прыгает. Кроме того, подтверждение появления требует
двух наблюдений с разрывом не более 600 мс, поэтому пропуск через кадр прямо
удваивает задержку уведомления.

Как записать: в матче открыть `Настройки` → карточка диагностики захвата →
`Записать 3 секунды`. Приложение соберёт 24 кадра с той же частотой, с какой
разбирает миникарту, и предложит сохранить файл.

Разметка намеренно грубее покадровой — рядом с записью кладётся файл с тем же
именем и суффиксом `.labels.json`:

```json
{
  "schemaVersion": 1,
  "visibleThroughout": ["Nasus", "Kayle"],
  "notes": "чем примечательна запись"
}
```

Перечисляются те, кто виден на карте **всю запись**. Размечать каждый значок на
каждом кадре никто не станет регулярно, а для измерения устойчивости этого и не
нужно.

Замер: `ReplayInspect --stability <запись> [<каталог модели>]`. Он показывает долю
кадров, на которых участник подтверждён, и худший пропуск подряд. Второе важнее:
средняя доля в 90 процентов с одним провалом в пять кадров хуже ровных 85.
