# Подготовка выпуска

TempoCue распространяется через файлы в GitHub Releases. Раздел GitHub Packages для приложения не используется: он предназначен прежде всего для пакетов, подключаемых как зависимости, а не для обычного Windows-установщика.

## Что создаётся

Сценарий выпуска формирует три файла в `artifacts/release/<версия>/`:

- `TempoCue-<версия>-win-x64.zip` — переносимая self-contained версия;
- `TempoCue-Setup-<версия>.exe` — установщик для текущего пользователя Windows;
- `SHA256SUMS.txt` — контрольные суммы обоих файлов.

Self-contained сборка включает необходимую среду .NET. Тестировщику не требуется отдельно устанавливать .NET SDK или Runtime.

Установщик размещает приложение в `%LocalAppData%\Programs\TempoCue`, добавляет ярлык в меню «Пуск» и по выбору пользователя — на рабочий стол. Для установки не нужны права администратора.

## Требования к компьютеру сборки

- Windows x64;
- закреплённая в `global.json` версия .NET SDK;
- Inno Setup 6.

## Сборка

Из корня репозитория выполнить:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build-release.ps1
```

Номер версии читается из `Directory.Build.props`. Перед выпуском он должен совпадать с тегом Git, например `0.2.0` и `v0.2.0`.

Проверочная сборка для своей машины собирается без установщика — Inno Setup для
неё не нужен:

```powershell
.\scriptsuild-release.ps1 -SkipInstaller
```

Такая сборка даёт только переносимый ZIP и не создаёт контрольных сумм: она не
предназначена для передачи кому-либо.

Если Inno Setup установлен в нестандартный каталог, путь можно передать явно:

```powershell
.\scripts\build-release.ps1 -InnoCompilerPath 'C:\Tools\Inno Setup 6\ISCC.exe'
```

## Сторонняя модель DeeperLeague удалена

Модель служила рабочим примером подключения ONNX и мерилом, против которого
принималось решение о собственной модели. Обе роли отыграны: своя модель берёт
64 чемпиона из 67 против её 48 из 60 и разбирает кадр за 8 мс против 160.

Код удалён в 0.6.0 вместе с выбором в настройках, ключом сборки
`-IncludeExperimentalModel` и режимами `--compare`, `--model`, `--model-raw`,
`--icons` инструмента ReplayInspect. Разбор эксперимента остаётся в
`docs/experiments/deeperleague.md` — он объясняет, почему собственная модель
вообще была начата, и переписывать его задним числом нельзя.

Заодно исчезло лицензионное обязательство: веса обучены через Ultralytics с
лицензией AGPL-3.0, и выпуск приходилось собирать так, чтобы они в него не
попали. Теперь их просто нет.

## Публикация на GitHub

1. Открыть тег нужной версии и создать GitHub Release.
2. Добавить описание изменений из `CHANGELOG.md`.
3. Прикрепить ZIP, EXE и `SHA256SUMS.txt` из каталога выпуска.
4. Для альфа-версии включить отметку prerelease.
5. Скачать оба варианта со страницы релиза и проверить запуск на другом компьютере.

Пока установщик не подписан сертификатом, Windows SmartScreen может показать предупреждение о неизвестном издателе. Это ожидаемо для ранней тестовой версии; предупреждение нельзя скрывать или выдавать установщик за подписанный.

## План релизов

### 0.5.0 — профили игроков и выбор чемпионов

Выпуск добавляет безопасно доступные Riot ID и ссылки на LeagueOfGraphs в активном матче,
а также отдельное состояние выбора чемпионов с ролями и выбранными чемпионами своей
команды. Скрытые и неоднозначные личности остаются анонимными. Исследовательские утилиты,
диагностические отчёты и способы обхода `HIDDEN` в выпуск не входят.

### 0.6.0 — отслеживание карты

Следующий выпуск посвящён наблюдению за картой, а не расширению статистического оверлея.
Планируемая граница:

- захват изображения только из игрового окна и области миникарты;
- распознавание наблюдаемых меток чемпионов и событий появления или исчезновения;
- факты «последний раз замечен» с игровым временем и оценкой уверенности;
- сигналы о пропавшем из вида сопернике и замеченном леснике;
- воспроизводимая проверка на обезличенных снимках и записях без необходимости запускать
  настоящий матч;
- безопасное состояние «неизвестно» при перекрытой, изменённой или неоднозначной карте.

Захват без системной цветной рамки Windows **сделан** и оказался дешевле, чем
планировалось. План требовал package identity (MSIX либо пакет с external location) и
объявления возможности `graphicsCaptureWithoutBorder`. Замер на живой Windows 11 показал,
что обычному приложению рабочего стола система выдаёт доступ по запросу
`GraphicsCaptureAccessKind.Borderless` **без пакета и без окна согласия**. Упаковка в MSIX
для этой цели не нужна.

На неподдерживаемой версии Windows или при отказе TempoCue продолжает работу с системной
рамкой и называет причину в карточке диагностики. Подробности — `docs/issues/`, запись TC-011.

**Направление движения лесника перенесено за границу выпуска.** Сигнал требует не
распознавания, а рассуждения о карте поверх него: куда участник шёл, откуда мог выйти,
чему это противоречит. Это отдельная работа, и делать её ради полноты списка, пока не
проверены базовые сигналы, преждевременно.

Распознавателем по умолчанию в выпуске идёт **модель TempoCue**: 64 чемпиона из 67 против
45 у штатного конвейера, вчетверо дешевле по времени кадра. Она не выполняет пункт 1
договора о приёмке — ложных один-два вместо нуля, — и это отступление записано с
обоснованием и условием снятия в `own-model-plan.md`. Штатный конвейер остаётся и
переключается списком в настройках.

**Сигналы наблюдения стали наборами контроля карты.** Появление вражеского лесника и
пропажа мидера больше не зашиты в код: это два обычных набора, которые включаются,
выключаются и переносятся так же, как наборы про драконов (ADR 0016). Формат
поддерживает всю матрицу «пять ролей на два события»; пошаговый редактор для них
отложен за границу выпуска.

Отсюда следует и вторая перемена: **наблюдение за картой останавливается целиком, когда
не включено ни одного правила наблюдения** (ADR 0017). Захват и разбор кадров — самая
дорогая часть приложения, и платить за них незачем, если результат некому слушать. Расход
процессора становится нулевым, а не меньшим; включается обратно за секунду. Выключатель
для игрока — тот же самый, что у драконов, отдельной настройки «выключить зрение» нет.

TempoCue не должен читать память игры, внедряться в процесс League или выдавать скрытое
положение противника за наблюдаемый факт. Отображение сигнала будет использовать уже
существующий контракт игровых уведомлений, но отдельная переработка оверлея не входит в
границу 0.6.0.

### Отложено за границу 0.6.0

- **Направление движения лесника.** Требует рассуждения о карте поверх
  распознавания, а не самого распознавания.
- **Ноль ложных подтверждений у модели.** Причина установлена и это не
  обучение, а шаг карты центров; отступление записано в `own-model-plan.md`.
- **Расширение корпуса приёмки.** Двенадцать кадров не доказывают ничего про
  ложные срабатывания, и мы сами это записали.
- **Пошаговый редактор правил наблюдения.** Формат допускает любую пару «роль и
  событие», но создавать их через окно создания правила пока нельзя: игрок
  пользуется двумя встроенными наборами и может править их копии как файлы.
- **Удаление штатного конвейера на OpenCV.** Решено 28 августа 2026 года
  оставить его в 0.6.0. Цена — 64 МБ из 247 в установке (`OpenCvSharpExtern.dll`
  61,9 МБ и `OpenCvSharp.dll` 2,5 МБ), и своей модели он не нужен вовсе: она
  работает на ONNX Runtime, а поиск области миникарты и отбор кадров — свой код.

  Держим по трём причинам. Первая: TC-004 — падение частоты кадров игры — не
  разобран, и второй распознаватель остаётся единственным способом проверить,
  причастно ли к нему распознавание. Вторая: все наши числа сравнения («64 из 67
  против 45», «8 мс против 39») получаются прогоном обоих путей на одном корпусе,
  и `--own-model`, `--stability`, `--timing` устроены как таблица с двумя
  колонками. Третья: модели три дня, и живых проверок пока считаные.

  Условие снятия: 0.6.0 прожил несколько недель на живых играх и TC-004 закрыт
  или объяснён. Тогда же решается судьба корпусных проверок — перенацелить на
  свою модель или заморозить числа сравнения как исторические. Заодно снимается
  загрузка портретов чемпионов из Data Dragon: модель берёт из состава только
  имена, пиксели портретов нужны именно OpenCV.

  Запасной путь при отказе модели в этот счёт не идёт: файлы модели лежат внутри
  приложения, и если их нет, нативных библиотек OpenCV тоже нет. Он спасает лишь
  от узкого случая «ONNX Runtime не запустился, а OpenCV работает».

### Последующие выпуски

Позднее отдельно рассматриваются статистический оверлей игроков, собственная история
матчей, послематчевый анализ и каталог сообщества. Эти направления не должны расширять
границу 0.6.0 до завершения и проверки базового отслеживания карты.
