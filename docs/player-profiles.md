# Riot ID и ссылки на профили игроков

## Область реализации 0.5.0

В TempoCue 0.5.0 первая часть профилей работает только после подключения к активному
матчу. В разделе `Текущий матч → Составы` для каждого участника отображаются:

- имя чемпиона;
- Riot ID в формате `gameName#tagLine`;
- компактная ссылка `LoG ↗` на профиль LeagueOfGraphs, если регион клиента определён.

До загрузки на карту TempoCue также может показать собственную команду на стадии выбора
чемпионов. Этот сценарий использует локальный League Client API и отделён от Live Client
Data. Для каждого слота отображаются назначенная роль, выбранный чемпион и состояние
личности.

Riot ID и ссылка на LeagueOfGraphs появляются только при одновременном выполнении двух
условий:

- League Client явно вернул для слота `nameVisibilityType = VISIBLE`;
- ответ профиля содержит корректные `gameName` и `tagLine`.

Значение `HIDDEN` всегда отображается как анонимный игрок. Отсутствующее, неизвестное или
изменившееся значение видимости считается недоступным: TempoCue не выполняет запрос
профиля и не пытается восстановить личность из других полей. Такое поведение соответствует
правилу Riot, запрещающему деанонимизацию игроков, которых нельзя обоснованно определить
по видимой пользователю информации.

## Источник данных

TempoCue продолжает выполнять один запрос полного снимка Live Client Data в секунду.
Дополнительный запрос на каждого участника не создаётся. Поля `riotId`, `riotIdGameName`
и `riotIdTagLine` входят в документированный ответ Riot `playerlist`, который уже является
частью `allgamedata`:

- [Riot Games: Live Client Data API](https://developer.riotgames.com/docs/lol#game-client-api_live-client-data-api).

В Core Riot ID представлен отдельным типом. Внутренний `ParticipantId` не используется
как отображаемое имя: он может быть запасным техническим значением и не гарантирует
наличия обеих частей Riot ID.

Для Champion Select адаптер `TempoCue.Riot` читает локальный lockfile запущенного League
Client и обращается к его HTTPS API на loopback-адресе. Этот API не является официально
поддерживаемым Riot интерфейсом, поэтому DTO изолированы внутри адаптера, отсутствие клиента
и изменение ответа представлены безопасными типизированными состояниями, а интеграция
должна быть раскрыта Riot при регистрации продукта. Токен из lockfile живёт только в памяти,
не попадает в Core, UI, журнал или диагностические файлы.

## Определение региона

Прямая ссылка LeagueOfGraphs содержит регион отдельным сегментом, например:

```text
https://www.leagueofgraphs.com/summoner/euw/Summoner+A-EUW
```

Тег Riot ID не определяет регион учётной записи, а язык приложения или League Client
может отличаться от региона сервера. Поэтому TempoCue один раз читает `region` из локальной
конфигурации установленного League Client:

```text
<League of Legends>/Config/LeagueClientSettings.yaml
```

Каталог установки находится через локальный манифест Riot Client. Если он недоступен,
используется путь запущенного процесса League. Чтение не требует LCU-токена, Riot API key
или сетевого запроса. Неизвестный либо неподдерживаемый регион не угадывается: Riot ID
остаётся в составе, а ссылка скрывается.

## Построение и открытие ссылки

- в URL попадают только проверенные части Riot ID;
- специальные символы экранируются как сегменты пути;
- ссылка создаётся только для разрешённого списка регионов LeagueOfGraphs;
- обработчик интерфейса открывает только HTTPS-ссылки с точным доменом
  `www.leagueofgraphs.com`;
- TempoCue сам не запрашивает страницу профиля и не анализирует её содержимое;
- Riot ID, регион и URL не записываются приложением на диск.
- Champion Select не выполняет запрос профиля для `HIDDEN`, отсутствующего или неизвестного
  значения `nameVisibilityType`;
- кеш видимых профилей существует только в памяти текущей сессии и очищается после выхода
  из Champion Select, ошибки клиента или завершения приложения.

## Автоматическая проверка

Тесты используют только вымышленные идентификаторы и временную конфигурацию League:

- DTO Riot правильно преобразуют как объединённое поле `riotId`, так и отдельные
  `riotIdGameName`/`riotIdTagLine`;
- некорректный Riot ID не попадает в пользовательскую модель;
- регион читается из тестовой установки без реального клиента;
- URL корректно экранирует пробелы и не создаётся для неизвестного региона;
- ViewModel сначала показывает Riot ID, а после определения региона добавляет ссылку.
- Champion Select запрашивает профиль только для явно видимого слота, не запрашивает его
  для скрытого или неопределённого слота и очищает временный кеш между сессиями.

## Ручная проверка

1. Запустить TempoCue и League Client.
2. Начать тренировочную или обычную игру и дождаться загрузки на карту.
3. Открыть `Текущий матч → Составы`.
4. Проверить наличие Riot ID у участников.
5. Нажать `LoG ↗` рядом с собственным Riot ID.
6. Убедиться, что браузер открыл ожидаемый профиль и регион URL совпадает с регионом
   учётной записи.
7. Завершить матч и убедиться, что состав очищен вместе с остальным состоянием матча.

### Champion Select

1. Запустить League Client и TempoCue.
2. Войти в обычное пользовательское лобби с выбором чемпионов.
3. Открыть `Текущий матч` и проверить, что до загрузки карты отображается отдельное
   состояние выбора чемпионов.
4. Убедиться, что выбранные чемпионы и назначенные роли обновляются, а скрытые слоты не
   содержат Riot ID и ссылок.
5. Если клиент явно сообщает видимый Riot ID, проверить ссылку `LoG ↗`.
6. Покинуть Champion Select и убедиться, что временный состав очищен.
7. Начать матч и убедиться, что экран переключился на данные Live Client Data.

Снимок реального ответа может содержать Riot ID. Перед сохранением в Git, тестовый fixture
или документ все идентификаторы необходимо заменить вымышленными значениями.
