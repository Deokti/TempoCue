# 0007. Отдельный адаптер Champion Select и граница приватности

- Статус: принято
- Дата: 2026-08-15

## Контекст

До загрузки матча Live Client Data недоступен, но TempoCue должен показать выбранных
чемпионов и роли собственной команды. Эти сведения есть в локальном League Client API.
Riot не считает этот API официально поддерживаемым: его контракт может измениться, а
некоторые очереди намеренно скрывают личности участников. Общая политика Riot запрещает
продукту деанонимизировать игрока, которого нельзя обоснованно определить по видимой
пользователю информации.

Нельзя распространять DTO, токен lockfile и нестабильные значения League Client по Core и
WPF. Нельзя также считать отсутствие признака скрытия разрешением на показ Riot ID.

## Решение

- Объявить в Application отдельный порт `IChampionSelectSource` с типизированными исходами.
- Реализовать доступ к локальному League Client в `TempoCue.Riot`; DTO, Basic-аутентификация
  и обход сертификата loopback остаются внутри адаптера.
- Создавать доменного участника с Riot ID и запрашивать его профиль только при точном
  значении `nameVisibilityType = VISIBLE`.
- Представлять `HIDDEN` как анонимного участника, а отсутствующее или неизвестное значение
  как недоступное. Для обоих состояний запрос профиля запрещён.
- Хранить кеш явно видимых профилей только в памяти текущей сессии и очищать его после
  выхода из Champion Select, ошибки клиента и завершения приложения.
- Использовать Champion Select только при отсутствии активного матча. Успешный снимок Live
  Client Data всегда имеет приоритет и исключает параллельный опрос Champion Select.
- Отображать это состояние на существующем экране текущего матча отдельным режимом.
- Раскрыть используемые локальные endpoints Riot при регистрации или обновлении продукта.

## Альтернативы

- Получать личности из других полей сессии или сопоставлять их с внешними данными. Отказались,
  потому что это обходит намеренную анонимность и нарушает политику Riot.
- Считать любое значение, кроме `HIDDEN`, видимым. Отказались: новый или отсутствующий enum
  создаст утечку при изменении внешнего контракта.
- Встроить League Client HTTP-запросы в ViewModel. Отказались из-за зависимости UI от
  нестабильного API, невозможности изолированного тестирования и риска распространения
  токена.
- Не показывать Champion Select вообще. Это безопаснее, но не даёт пользователю полезного
  состояния до загрузки карты и не проверяет нужный сценарий версии 0.5.0.

## Последствия

Core получает только нормализованное состояние и не знает источник Riot. Приватность можно
проверить unit-тестами через факт отсутствия запроса профиля. Изменение League Client API
локализуется в одном адаптере и не должно ломать UI или доменную модель.

Цена решения — ещё один локальный источник и необходимость сопровождать неподдерживаемый
контракт Riot. При неизвестном ответе интерфейс намеренно показывает меньше данных. Перед
публичным выпуском сценарий требуется проверить вручную в разрешённых очередях и раскрыть
Riot в описании интеграции.
