# Проверка подключения к активному матчу

TempoCue обращается к локальному endpoint League of Legends:

```text
https://127.0.0.1:2999/liveclientdata/allgamedata
```

Пока игровой процесс League of Legends не запущен, TempoCue проверяет только наличие
процесса и не открывает заведомо недоступное HTTPS-соединение. Это сохраняет автоматическое
обнаружение матча, но исключает сетевые таймауты и лишнюю нагрузку в простое.

Обычный серверный Riot API key для этого запроса не требуется. Опрос выполняется один раз в секунду.

Пока игровой процесс уже запущен, но Live Client Data ещё не готов, TempoCue
показывает статус `ЗАГРУЗКА МАТЧА`. Недоступность данных на этом переходе не
считается ошибкой подключения.

## Ограничение счётчика фарма

Эксперимент в тренировочном матче подтвердил, что `scores.creepScore` в общем
ответе и отдельном `/playerscores` округляется вниз до десятков: 15 CS в игре
возвращаются как 10, а 21 — как 20. Поэтому TempoCue отображает значение со
знаком приблизительности, например `≈20 CS`, и не выдаёт его за точное.
Отдельный запрос не повышает точность, поэтому приложение получает показатели
всех игроков из единственного полного снимка `/allgamedata` раз в секунду.

Для точного отслеживания фарма, в том числе маршрута лесника, потребуется другой
разрешённый источник данных. Это ограничение нужно учитывать до реализации такой логики.

## Подготовка

1. Запустить TempoCue командой:

   ```powershell
   dotnet run --project src/TempoCue.App
   ```

2. Убедиться, что в правой верхней части окна отображается статус `ОЖИДАНИЕ МАТЧА`.
3. Открыть вкладку `JSON АКТИВНОГО МАТЧА` — она выбрана при запуске автоматически.
4. Запустить custom game на Summoner's Rift.
5. Выбрать Urgot, а второму игроку выбрать Sett.

## Ожидаемый результат

Не позднее чем через несколько секунд после загрузки на карту:

- статус меняется на `МАТЧ ПОДКЛЮЧЕН`;
- отображаются чемпион пользователя, игровое время и число участников;
- во вкладке появляется форматированный JSON;
- движок автоматически определяет матчап Urgot против Sett;
- показывается совет для текущего уровня и предметов;
- при смене активного правила в журнал добавляется новая запись.

Опрос выполняется каждую секунду, но одинаковый совет не добавляется в журнал повторно.

## Что проверить в JSON

Для первого теста особенно важны поля:

```text
activePlayer.riotId
allPlayers[].championName
allPlayers[].team
allPlayers[].position
allPlayers[].level
allPlayers[].items[].itemID
gameData.gameTime
```

Если матч подключился, но совет не определился, нажать `Копировать JSON` и сохранить ответ для диагностики.

JSON может содержать Riot ID участников. Перед добавлением такого файла в Git или отправкой третьим лицам идентификаторы нужно заменить тестовыми значениями.

## Окончание матча

После выхода из игры статус возвращается к `ОЖИДАНИЕ МАТЧА`. В диагностической вкладке сохраняется последний успешный JSON, чтобы его можно было изучить после теста.
