# Контроль карты

## Граница версии 0.4.0

Первая версия контроля карты использует игровое время и подтверждённые события Riot Live Client Data. Анализ миникарты, распознавание перемещений, варды и определение видимости противников в эту версию не входят.

Патч-зависимые тайминги и правила напоминаний принадлежат `TempoCue.Coaching`. Нормализованные игровые события об объектах остаются фактами `TempoCue.Core`. Интерфейс выбирает правила и показывает результат, но не вычисляет появление объектов самостоятельно.

После выхода нового патча TempoCue продолжает использовать последние проверенные тайминги и возвращает признак `IsUsingPreviousPatchData`. Интерфейс должен показать пользователю патч последней проверки, но не отключать Coach Pack и уведомления. Полный отказ допустим только для некорректного номера патча или версии старше первой поддерживаемой базы.

## Проверенные тайминги Summoner's Rift

Для публичного патча Riot 26.15, соответствующего ветке Data Dragon 16.15:

| Объект               | Первое появление |       Повторное появление |
|----------------------|-----------------:|--------------------------:|
| Элементальный дракон |             5:00 | через 5:00 после убийства |
| Личинки Бездны       |             8:00 |               отсутствует |
| Герольд Бездны       |            15:00 |               отсутствует |
| Барон Нашор          |            20:00 | через 6:00 после убийства |

Каталог хранит две подтверждённые точки изменения:

- с 15.9 Личинки появляются в 8:00 один раз, а Герольд — в 15:00;
- с 16.1 Барон появляется в 20:00 вместо 25:00.

Источники Riot:

- [Patch 25.09 Notes](https://www.leagueoflegends.com/en-us/news/game-updates/patch-25-09-notes/) — изменение Личинок и Герольда;
- [Patch 26.1 Notes](https://www.leagueoflegends.com/en-us/news/game-updates/patch-26-1-notes/) — возвращение Барона на 20:00 и подтверждение, что остальные тайминги эпических объектов не менялись;
- [Patch 9.23 Notes](https://www.leagueoflegends.com/en-us/news/game-updates/patch-9-23-notes/) — базовое первое появление и интервал элементальных драконов.

Интервалы повторного появления применяются только после подтверждённого события убийства объекта. Пока Riot-событие для конкретного объекта не распознано, TempoCue может напоминать о первом появлении, но не должен угадывать время следующего.

## Правила напоминаний

Правило привязано к одному нейтральному объекту и одному наблюдаемому факту:

- за указанное время до первого появления объекта;
- непосредственно в момент первого появления;
- за указанное время до повторного появления после подтверждённого убийства;
- непосредственно после подтверждённого убийства.

Для событий, которые могут повторяться, автор выбирает одно срабатывание за матч или
срабатывание в каждом цикле. Планировщик в `TempoCue.Coaching` получает уже нормализованные
события убийства и строит стабильные идентификаторы и моменты срабатывания. Он не зависит
от Riot JSON, активного окна приложения и способа показа уведомления.

Для правила первого появления режим «каждый доступный цикл» включает само первое появление,
а затем добавляет срабатывание для каждого возрождения после подтверждённого события убийства.
Без события Riot TempoCue не угадывает время следующего появления. Для объекта без известного
цикла возрождения этот режим недоступен.

Перезапуск таймера после убийства применяется только к объектам, для которых каталог
знает время повторного появления. Поэтому правила повторного появления нельзя создать
для Личинок Бездны и Герольда Бездны в актуальном наборе таймингов.

## Переносимый Map Control Pack

Контроль карты использует отдельный корневой JSON-формат `MapControlPack`, а не расширяет
матчапный `CoachPack`. Это позволяет независимо развивать условия объектов и фазы матчапа,
не меняя смысл уже опубликованных файлов.

Первая версия схемы содержит:

- `packType: "mapControl"` для безопасного определения типа при общем импорте;
- идентификатор, название, патч, описание, автора и язык содержимого;
- дату проверки и источник знаний;
- происхождение копии, если пользователь дорабатывает чужой набор;
- область применения: непустой набор ролей и сторону команды активного игрока;
- упорядоченный список правил `MapObjectiveReminderRule`;
- на третьем шаге редактора правила объектов создаются через каталог таймингов выбранного патча;
- пользователь выбирает объект, триггер, упреждение, повторение, приоритет и текст совета, но не редактирует системное время появления;
- отключённые правила сохраняются в наборе, но планировщик не создаёт для них срабатывания;
- постоянные подсказки хранят заголовок, текст и область применения;
- напоминания по игровому времени хранят точку срабатывания с шагом 15 секунд, приоритет, название, главный совет, объяснение и необязательное поле «Что подготовить к объекту»;
- каждое напоминание по времени срабатывает не более одного раза за матч, а редактор автоматически сортирует карточки по времени.

При чтении и записи файл проверяется целиком. Набор отклоняется при неподдерживаемой версии
или типе, неполных метаданных, повторяющихся идентификаторах, неизвестном объекте и правиле,
которое противоречит проверенным таймингам его патча. Для будущего патча разрешено использовать
последние проверенные тайминги с явным признаком устаревших знаний; некорректный или слишком
старый патч не принимается.

Application предоставляет отдельные сценарии сохранения, загрузки, импорта, экспорта,
переключения и удаления `MapControlPack`. Файловый адаптер хранит пользовательские наборы в
`%LocalAppData%/TempoCue/MapControlPacks`, отдельно от матчапов в `CoachPacks`. Содержимое и
локальное состояние «черновик/включён/выключен» записываются раздельно. Импортированный файл
может заменить только прежнюю импортированную установку с тем же ID; встроенный или созданный
пользователем набор защищён от такой замены.

## Пошаговый редактор

Редактор Map Control Pack развивается проверяемыми итерациями и использует отдельную
модель навигации из пяти шагов: основная информация, область применения, содержание,
проверка и сохранение. Пользователь может перейти только на уже пройденный шаг или на
следующий шаг после успешной проверки текущего; пропуск незаполненных шагов запрещён.

Первая UI-итерация реализует основную информацию: название, краткое описание, язык
содержимого и игровой патч. Выбор патча использует общий с матчапным редактором каталог,
включая текущий патч, кеш и повторную загрузку. В версии 0.4.0 карта зафиксирована как
Summoner's Rift.

Вторая UI-итерация добавляет область применения. Автор выбирает одну или несколько ролей
активного игрока и любую, синюю либо красную сторону команды. Пустой набор ролей запрещён,
а итоговое резюме обновляется сразу. Обычные и ранговые матчи пока не разделяются: первая
версия не получает достаточно надёжного сигнала, поэтому интерфейс не предлагает условие,
которое приложение не сможет гарантированно проверить. Ограничения сохраняются в
`MapControlPack.Applicability`.

Третья UI-итерация реализует первый тип содержимого — правила объектов. Автор выбирает объект из
каталога таймингов патча, момент срабатывания, упреждение, повторение, приоритет и текст совета.
Системные тайминги нельзя изменить вручную; недоступные для объекта триггеры блокируются. Правила
можно включать, упорядочивать, редактировать, дублировать и удалять. Для перехода к проверке достаточно
хотя бы одного завершённого элемента любого типа: объектного правила, напоминания по времени или постоянной подсказки.

Следующая итерация того же шага добавляет постоянные подсказки. Они служат справочным материалом
в деталях набора: сами по себе не всплывают в оверлее и не вытесняют активное напоминание. Автор
задаёт заголовок, текст и одну область применения: весь матч, период до первого объекта, время
доступности любого объекта либо конкретный объект. Подсказки можно упорядочивать, редактировать,
дублировать и удалять; их отсутствие не блокирует переход дальше. Напоминания по игровому времени
также необязательны: автор вводит минуты либо четыре цифры в формате ММСС, задаёт момент с шагом 15 секунд,
приоритет и полный текст совета, а список
автоматически сохраняет хронологический порядок. Каждое такое напоминание срабатывает один раз за матч.

Четвёртый шаг повторно проверяет метаданные, область применения и содержимое, показывает ошибки и
предупреждения, а также строит временную шкалу только по системным событиям выбранных объектных правил
и пользовательским напоминаниям. Ошибки блокируют переход, предупреждения оставляют набор доступным
для сохранения после осознанной проверки автором.

Пятый шаг собирает источник знаний и итоговую карточку набора. Для личного опыта дополнительные поля
не нужны; для статьи, видео или тренерских материалов обязательны название и автор, а HTTP(S)-ссылка
остаётся необязательной. Набор можно сохранить черновиком либо сразу включить. После успешной записи
редактор возвращает пользователя в библиотеку, а файл и его локальное состояние сохраняются раздельно
в `%LocalAppData%/TempoCue/MapControlPacks`.

## Библиотека

Вкладка «Контроль игры» загружает сохранённые `MapControlPack` из отдельного хранилища и
показывает для каждого набора название, область ролей, автора, число элементов, состояние,
происхождение, язык и патч. Поиск учитывает название, описание и автора. Переключатель меняет
только локальное состояние «включён/выключен» и не переписывает переносимый JSON.

Карточка открывает подробный просмотр с вкладками обзора, правил объектов, напоминаний по
времени и постоянных подсказок. Из карточки и подробного просмотра доступны экспорт файла и
удаление локального набора. Собственный набор можно редактировать, а для добавленного из
библиотеки создаётся отдельная копия без изменения оригинала.

Общая кнопка импорта автоматически различает матчапный и Map Control Coach Pack по типу
переносимого файла. Перед записью показывается проверенный предпросмотр метаданных и содержимого.
Новый импортированный набор добавляется выключенным; повторный импорт может заменить только
предыдущую импортированную установку с тем же идентификатором и сохраняет её локальное состояние.
